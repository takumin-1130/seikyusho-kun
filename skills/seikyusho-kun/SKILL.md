# 請求書くん

`seikyusho-kun` は請求書PDFを発行するCLIです。このスキルは、ユーザーの言葉から
必要な情報を拾って、正しいコマンドに変換するための手引きです。

## 大原則

1. **確認なしに勝手に発行しない**。発行内容（宛先・名目・金額・締日／有効期限）を一度示して、
   ユーザーが「OK」と言ってから実行します。請求書も見積書も同じです。
2. **メールは絶対に勝手に送らない**。`send` は既定で文面を表示するだけです。
   文面を見せて承認をもらってから `--yes` を付けます。
3. **金額と宛先は推測しない**。聞かれていない金額を埋めたり、似た名前の取引先を
   勝手に選んだりしないでください。わからなければ聞きます。

## 使う前に

```bash
seikyusho-kun doctor
```

- 「設定ファイル 未作成」と出たら、まず `seikyusho-kun init` をユーザー自身に
  実行してもらってください（屋号・振込先・インボイス登録番号を対話で聞く画面が出ます）。
  **この対話はあなたが代行できません**。ユーザーにターミナルで実行してもらいます。
- 「Chrome が見つかりません」と出たら、Google Chrome の導入が必要です。

## 1. 請求書を発行する

必要なのは **宛先・名目・金額・締日** の4つです。

```bash
seikyusho-kun new --to "株式会社ABC" --item "ホームページ制作費" --amount 150000 --due 月末 --yes
```

### ユーザーの言葉からの拾い方

| 言われ方 | 渡す値 |
|---|---|
| 「ABC社に」「株式会社ABCさんに」 | `--to "株式会社ABC"` |
| 「HP制作費で」「AI講習の分」 | `--item "ホームページ制作費"` |
| 「15万」「150,000円」「15万円」 | `--amount 15万`（そのまま渡してよい） |
| 「月末締めで」「今月末」 | `--due 月末` |
| 「来月末で」 | `--due 翌月末` |
| 「9月30日まで」 | `--due 2026-09-30` |
| 「30日以内」 | `--due 30日後` |
| 「担当の山田さん宛て」 | `--contact "山田 太郎"` |

**締日が言われていないときは `--due 月末` を提案し、それでいいか確認します。**
勝手に決めて発行しないでください。

### 明細が複数あるとき

`--item` を書くたびに新しい行になります。数量・単位・税率は **その直前の
`--item` に紐づく** ので、順番どおりに並べます。

```bash
seikyusho-kun new --to "株式会社ABC" \
  --item "ホームページ制作費" --amount 300000 \
  --item "写真撮影" --amount 50000 --qty 4 --unit 点 \
  --item "月額保守" --amount 60000 --qty 12 --unit ヶ月 \
  --due 翌月末 --yes
```

### 軽減税率・源泉徴収

- 軽減税率(8%)の品目には `--rate 8` を付けます。税率ごとに区分された
  適格請求書の形式で出ます。
- 源泉徴収は `init` の設定（`tax.withholding`）で決まります。個別の請求書だけ
  変えることはできないので、必要なら設定変更をユーザーに案内してください。

### よく使うオプション

| オプション | 用途 |
|---|---|
| `--open` | 出したPDFをすぐ開く（ユーザーに見せたいとき便利） |
| `--out <パス>` | 保存先を指定する |
| `--html` | PDFではなくHTMLを出す（下書き。請求書番号を消費しない） |
| `--theme <名前>` | 今回だけデザインを変える |
| `--notes "..."` | 備考欄に一文足す |
| `-y, --yes` | 対話せずに実行する（**あなたが呼ぶときは必ず付ける**） |

`--yes` を付けないと対話画面が開いて固まります。CLIから呼ぶときは常に付けてください。

## 2. 見積書を発行する

必要なのは **宛先・名目・金額** の3つです。有効期限は既定(発行日から1ヶ月後)が使われます。

```bash
seikyusho-kun mitsumori --to "株式会社ABC" --item "撮影一式" --amount 400000 --yes
```

明細の書き方(`--item` を並べる、数量・単位は直前の `--item` に付く)、金額の読み取り、
軽減税率の扱いは **請求書とまったく同じ** です。

### 見積書だけの拾い方

| 言われ方 | 渡す値 |
|---|---|
| 「見積出して」「見積書作って」「いくらになるか出して」 | `mitsumori` コマンドを使う |
| 「有効期限は2ヶ月で」「来月末まで有効で」 | `--valid 2ヶ月後` / `--valid 翌月末` |
| 「諸経費10%で」 | `--expenses 10%`（ほかの明細の合計に対する率） |
| 「諸経費3万足して」 | `--expenses 30000` |
| 「納期は発注後30日」「11月30日納品で」 | `--delivery "ご発注後30日"` / `--delivery 2026-11-30` |
| 「MP4のフルHDで納品」 | `--format "MP4 / H.264 / 1920×1080"` |
| 「修正2回まで」 | `--revisions "初稿提出後2回まで"` |

**請求書と同じく、発行内容(宛先・名目・金額・有効期限)を示して承認をもらってから実行します。**

### 見積書で間違えやすいこと

- 見積書に**振込先は出ません**。**源泉徴収も引きません**。これは仕様なので「抜けている」と
  報告しないでください
- 見積書番号は請求書と**別の連番**です(既定 `Q202610-001`)
- 発行済みの見積書は `seikyusho-kun mitsumori list` で一覧できます
- 有効期限が言われていないときは、既定(1ヶ月後)でよいか一言確認します

## 3. 受注したら請求書に変換する

「あの見積、受注したから請求書にして」と言われたときは、打ち直さずに変換します。

```bash
seikyusho-kun new --from-quote Q202610-001 --due 月末 --yes
```

- 宛先・担当者・明細(諸経費の行も含む)がそのまま引き継がれます
- 見積書番号が分からなければ `seikyusho-kun mitsumori list` で確認します。
  取引先名でも引けます(`--from-quote ABC` → その取引先のいちばん新しい見積書)
- **締日は推測しません**。言われていなければ `--due 月末` を提案して確認します
- 一部だけ変えて請求するときは `--item` を書くと、そちらが優先されます
- すでに請求済みの見積書を指定すると警告が出ます。意図したものか確認してください

## 4. 取引先

```bash
seikyusho-kun clients list          # 登録済みの一覧
seikyusho-kun clients show "ABC"    # 1社の詳細
```

一度発行すると自動で登録されるので、2回目からは正式名称を `clients list` で
確かめてから `--to` に渡すと表記ゆれを防げます。

## 5. メールで送る

**必ず2段階で行います。**

```bash
# 手順1: 文面を確認する（送信しない）
seikyusho-kun send "株式会社ABC"
```

出てきた宛先・件名・添付・本文を **そのままユーザーに見せて** 承認をもらいます。

```bash
# 手順2: 承認をもらってから送る
seikyusho-kun send "株式会社ABC" --yes
```

- テスト送信は `--to 自分のアドレス` を付けます。
- 「メール送信が未設定です」と出たら `seikyusho-kun send --setup` を
  ユーザー自身に実行してもらいます（APIキーを入力する対話なので代行不可）。

## 6. 毎月の自動発行

```bash
seikyusho-kun schedule list              # 今の設定
seikyusho-kun run-due --dry-run          # 今日発行される分の下見
seikyusho-kun run-due --dry-run --date 月末   # 月末に何が出るかの下見
```

設定の追加（`schedule add`）と自動実行の登録（`schedule install`）は対話や
OSへの登録を伴うので、コマンドを提示してユーザーに実行してもらってください。

自動メール送信は取引先ごとに `email: true` を明示した場合だけ働きます。
**あなたの判断でこれを有効にしないでください。**

## 7. テンプレートを自分の会社のものに合わせる

ユーザーが「うちの請求書のフォーマットに合わせたい」と言ったときの手順です。

```bash
seikyusho-kun theme eject plain --as mine
```

`~/.seikyusho-kun/templates/mine/` に次の3つが出ます。

| ファイル | 役割 |
|---|---|
| `theme.css` | **ここを編集する。** 色・線・余白・文字サイズ |
| `invoice.njk` | 構造そのものを変えたいとき（Nunjucks = Jinja2 とほぼ同じ記法） |
| `base.reference.css` | 共通の骨格。読むだけ。上書きは `theme.css` で |

### 寄せ方の手順

1. ユーザーに **今使っている請求書**（PDF・画像・Excelのスクリーンショット）を
   見せてもらう
2. 読み取るのは：ロゴの位置 / 色 / 罫線の太さ / 項目名の言い回し
   （「合計金額」か「ご請求金額」か等）/ 明細の列構成 / 押印欄の有無
3. `theme.css` を編集する
4. **必ず出力を見て確かめる**:
   ```bash
   seikyusho-kun theme use mine
   seikyusho-kun new --to "テスト商事株式会社" --item "テスト項目" --amount 100000 --due 月末 --yes --out /tmp/preview.pdf
   ```
   出たPDFを開いて、元の請求書と見比べます。**CSSを書いただけで「できました」と
   言わないでください。**

### 崩さないための注意

- ヘッダーは `.hd`、フッターは `.ft`、明細表は `.items` です。
  `.ft` の `margin-top: auto` を消すとフッターが紙の下端に行かなくなります。
- 明細が増えたときは `body.d2` 〜 `body.d4` の密度段が自動で効きます。
  `theme.css` で文字サイズを固定値で上書きすると、この自動調整が壊れます。
  変えるなら `--fs` などの CSS変数を上書きしてください。
- 変更後は明細1件と20件の両方でPDFを出して、1ページに収まるか確かめます。

## 8. 発行後に別のシステムへ流したい

`~/.seikyusho-kun/config.json` に次を足すと、発行のたびに任意のコマンドが走ります。

```json
"hooks": { "afterIssue": "~/bin/my-sync.sh" }
```

環境変数で `INVOICE_PDF` `INVOICE_NO` `CLIENT_NAME` `INVOICE_TOTAL`
`INVOICE_PAYABLE` `INVOICE_DUE_DATE` `INVOICE_JSON` が渡ります。
会計ソフトや台帳への転記はここに繋ぎます。

## 困ったときの調べ方

| 症状 | 見るところ |
|---|---|
| PDFが出ない | `seikyusho-kun doctor` |
| どこに保存されたか分からない | `seikyusho-kun list`（見積書は `seikyusho-kun mitsumori list`） |
| 2ページになってしまう | 出力ログの「A4 2ページ」表示。明細の文字数を減らすか `--theme compact` |
| 取引先名の表記が違う | `seikyusho-kun clients list` で正式名称を確認 |
| 番号が飛んだ | `~/.seikyusho-kun/counter.json`。`--no` で明示指定もできる |
| 見積書に振込先が無い | 仕様です。支払い段階ではないため出していません |
| 見積書から請求書にしたい | `seikyusho-kun new --from-quote <見積書番号> --due 月末` |

データはすべて `~/.seikyusho-kun/` にあります（設定・取引先・発行台帳・見積台帳・ログ）。
見積書の詳しい説明は `docs/見積書.md` にあります。
